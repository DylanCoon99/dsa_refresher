### Task 22: Topic 19 Tries

`TOPIC=19_tries`, `NN=19`. `trie` is both the Implement item and "Implement Trie (Prefix Tree)".

**Diagnostic picks:** `word_dictionary`, `word_search_ii`.

**Exercises:**

- **`trie`** · Implement + Practice · Medium
  - Sig: `class Trie { public: Trie(); ~Trie(); Trie(const Trie&) = delete; Trie& operator=(const Trie&) = delete; void insert(const std::string& word); bool search(const std::string& word) const; bool startsWith(const std::string& prefix) const; };`
  - Contract: lowercase a–z. The empty string may be inserted and searched. PROBLEM.md mentions the fixed-array vs map child trade-off.
  - Tests: a prefix is not a word until inserted; `startsWith("")` → true; inserting twice; 10⁴ random ops against a `std::set` + prefix scan; destroy 100 tries (ASan catches a double free).
  - Large: 10⁵ words of length 20, then 10⁵ queries. A linear scan over the words is 10¹⁰.
  - PROBLEM.md note: "Mastery: under 10 minutes from memory."
  - CLRS: the end-of-chapter problem "Radix trees" in Ch. 12 (3e and 4e) is the only coverage (≈5 min). The plan says to prefer the hints.
- **`word_dictionary`** · Medium
  - Sig: `class WordDictionary { public: void addWord(const std::string& word); bool search(const std::string& word) const; };`
  - Contract: `.` matches any one letter.
  - Tests: all dots; dots longer than any word; a dot at the end; mixed literal and dot.
  - Large: 10⁴ words, 10⁴ searches of `"..."`-style patterns of length 3–5.
- **`word_search_ii`** · Hard
  - Sig: `std::vector<std::string> findWords(std::vector<std::vector<char>> board, const std::vector<std::string>& words)`
  - Contract: any order; each word at most once.
  - Tests: normalize; the same word reachable two ways appears once; a word needing a reused cell → absent; a 1×1 board.
  - Large: a 12×12 board of random letters from `abc` with 3·10⁴ random words of length 1–10. Running word_search per word is too slow.
  - PROBLEM.md hint: prune trie nodes once their word is found.

### Task 23: Topic 20 Range Query Structures

`TOPIC=20_range_queries`, `NN=20`.

**Diagnostic picks:** `range_sum_mutable`, `my_calendar_i`.

**Exercises:**

- **`fenwick_tree`** · Implement · Medium
  - Sig: `class FenwickTree { public: explicit FenwickTree(int n); void add(int i, long long delta); long long prefixSum(int i) const; long long rangeSum(int l, int r) const; };`
  - Contract: 0-indexed API (convert to 1-indexed inside). `prefixSum(i)` = sum of [0, i]; `prefixSum(-1)` = 0. `rangeSum` is inclusive.
  - Tests: n = 1; `rangeSum(0, n−1)`; negative deltas; 10⁴ random ops against a brute-force array.
  - Large: n = 10⁶ with 10⁶ mixed ops.
  - PROBLEM.md note: "Mastery: from memory."
- **`segment_tree`** · Implement · Hard
  - Sig: `class SegmentTree { public: explicit SegmentTree(const std::vector<long long>& values); void update(int i, long long value); long long query(int l, int r) const; };`
  - Contract: point assignment (not add); inclusive range sum. Lazy propagation is described in PROBLEM.md as an optional extension, with no tests.
  - Tests: n = 1; n not a power of two (n = 7); 10⁴ random ops against brute force.
  - Large: n = 10⁵ with 10⁵ ops.
  - CLRS: Ch. 14 (3e) / Ch. 17 (4e), "Augmenting Data Structures": read the §14.2 (3e) / §17.2 (4e) intro, "How to augment a data structure" (≈10 min), for the general idea. Segment trees themselves aren't in CLRS.
- **`range_sum_mutable`** · Medium
  - Sig: `class NumArray { public: explicit NumArray(const std::vector<int>& nums); void update(int index, int val); int sumRange(int left, int right) const; };`
  - Tests: update to the same value; update the first and last positions; random ops against brute force.
  - Large: n = 10⁵ with 10⁵ alternating ops. Rebuilding prefix sums on each update is O(n²).
- **`count_smaller_after_self`** · Hard
  - Sig: `std::vector<int> countSmaller(const std::vector<int>& nums)`
  - Tests: equal values aren't smaller; negatives; INT_MIN/INT_MAX (coordinate compression needed for a Fenwick tree); against O(n²) brute force.
  - Large: n = 10⁵.
  - CLRS: §14.1 (3e) / §17.1 (4e), "Dynamic order statistics": OS-RANK is the same "how many smaller" query on an augmented tree (≈15 min).
- **`my_calendar_i`** · Medium
  - Sig: `class MyCalendar { public: bool book(int start, int end); };`
  - Contract: half-open [start, end).
  - Tests: touching bookings succeed; nested bookings fail; a booking identical to an existing one fails.
  - Large: 10⁵ non-overlapping bookings in random order. A list scan is O(n²).
  - CLRS: §14.3 (3e) / §17.3 (4e), "Interval trees": INTERVAL-SEARCH (≈15 min). A `std::map` with `lower_bound` is the practical equivalent.

**CLRS quick reference rows:**
- Augmentation idea: §14.2 / §17.2, ≈10 min.
- Order-statistic trees: §14.1 / §17.1, ≈15 min.
- Interval trees: §14.3 / §17.3, ≈15 min.
- Fenwick and segment trees: not in CLRS.

### Task 24: Topic 21 String Algorithms

`TOPIC=21_strings`, `NN=21`.

**Diagnostic picks:** `longest_palindromic_substring`, `strstr_kmp`.

**Exercises:**

- **`kmp`** · Implement · Hard
  - Sig: `std::vector<int> prefixFunction(const std::string& s)` and `std::vector<int> kmpSearch(const std::string& text, const std::string& pattern)`
  - Contract:
    - `prefixFunction` returns π, where π[i] is the length of the longest proper prefix of s[0..i] that is also a suffix;
    - `kmpSearch` returns every start index, overlapping matches included;
    - an empty pattern returns an empty result.
  - Tests:
    - π for `"aabaaab"` → {0,1,0,1,2,2,3};
    - overlapping matches (`"aaaa"` / `"aa"` → {0,1,2});
    - the pattern longer than the text;
    - against a naive search on 500 random binary strings.
  - Large: text "a"×10⁶, pattern "a"×999 + "b". Naive is ~10⁹ comparisons.
  - CLRS: §32.4 (3e) / §32.4 (4e), "The Knuth-Morris-Pratt algorithm": COMPUTE-PREFIX-FUNCTION and KMP-MATCHER (≈20 min). Skip if you can explain what π[i] means and why the matcher is linear.
- **`rolling_hash`** · Implement · Medium
  - Sig: `class RollingHash { public: explicit RollingHash(const std::string& s); std::uint64_t hash(std::size_t pos, std::size_t len) const; };`
  - Contract: O(n) preprocessing and O(1) per query; polynomial hash. Equal substrings must give equal hashes, including across different `RollingHash` objects.
  - Tests:
    - `hash(pos,len)` equals `RollingHash(s.substr(pos,len)).hash(0,len)`;
    - anagrams hash differently (`"ab"` vs `"ba"`), which catches sum-of-chars hashes;
    - all substrings of 300 random strings over `ab` of length 12: distinct substrings give distinct hashes (with a 64-bit modulus a collision here is essentially impossible).
  - Large: n = 10⁶ with 10⁶ queries. Hashing each substring from scratch is too slow.
  - CLRS: §32.2 (3e) / §32.2 (4e), "The Rabin-Karp algorithm": the rolling update formula (≈15 min).
- **`strstr_kmp`** · Easy
  - Sig: `int strStr(const std::string& haystack, const std::string& needle)`
  - Contract: first index or −1. PROBLEM.md says "solve with KMP" (the plan).
  - Tests: needle == haystack; needle longer; a match at the end.
  - Large: the same input as `kmp`.
- **`repeated_string_match`** · Medium
  - Sig: `int repeatedStringMatch(const std::string& a, const std::string& b)`
  - Tests: b already inside a → 1; impossible → −1; a match that needs the boundary wrap (`"abcd"` / `"cdabcdab"` → 3).
- **`longest_palindromic_substring`** · Medium
  - Sig: `std::string longestPalindrome(const std::string& s)`
  - Contract: any valid answer.
  - Tests: validate (it's a substring, it's a palindrome, and its length equals the brute-force max); a single char; even-length palindromes; all the same char.
  - Large: n = 5000 of a single char. The O(n³) brute force times out.
- **`palindromic_substrings`** · Medium · Sig: `int countSubstrings(const std::string& s)` · Tests: `"abc"` → 3; `"aaa"` → 6; against O(n³). · Large: n = 5000.
- **`longest_duplicate_substring`** · Hard
  - Sig: `std::string longestDupSubstring(const std::string& s)`
  - Contract: any valid answer; "" if none.
  - Tests: validate (occurs at least twice, possibly overlapping); length equal to brute force for n ≤ 60; all distinct chars → ""; `"aaaa"` → `"aaa"`.
  - Large: n = 3·10⁴ random letters from `ab`. O(n²) substring comparison is too slow under ASan; binary search plus rolling hash passes.
  - PROBLEM.md hint: verify hash hits by direct comparison.

**CLRS quick reference rows:**
- Naive matching: §32.1 / §32.1, ≈5 min.
- Rabin-Karp: §32.2 / §32.2, ≈15 min.
- KMP: §32.4 / §32.4, ≈20 min.
- Z-algorithm and Manacher: not in CLRS.

### Task 25: Topic 22 Advanced Graph Topics

`TOPIC=22_advanced_graphs`, `NN=22`. Reference solutions may use recursive DFS, since large tests keep depth ≤ 2·10⁴. PROBLEM.md notes the iterative form for production use.

**Diagnostic picks:** `eventual_safe_states`, `reconstruct_itinerary`.

**Exercises:**

- **`tarjan_bridges_ap`** · Implement · Hard
  - Sig: `std::vector<std::pair<int,int>> findBridges(int n, const Graph& adj)` and `std::vector<int> findArticulationPoints(int n, const Graph& adj)`
  - Contract: undirected; bridges are returned as (min, max) pairs; both results in any order.
  - Tests:
    - normalize;
    - a tree (every edge is a bridge);
    - a cycle (no bridges);
    - two cycles joined by an edge;
    - a disconnected graph;
    - parallel edges (a doubled edge is not a bridge, so track the edge index, not the parent vertex);
    - against brute force (remove each edge or vertex and count components) for n ≤ 12.
  - Large: 2·10⁴ vertices with 6·10⁴ edges. Brute force is O(E·(V+E)).
  - CLRS: the end-of-chapter problem "Articulation points, bridges, and biconnected components" in Ch. 22 (3e) / Ch. 20 (4e) (≈20 min).
- **`critical_connections`** · Hard
  - Sig: `std::vector<std::vector<int>> criticalConnections(int n, const std::vector<std::vector<int>>& connections)`
  - Tests: normalize both levels; n = 2 with a single edge; a triangle → none.
  - Large: the same size as above.
- **`eventual_safe_states`** · Medium
  - Sig: `std::vector<int> eventualSafeNodes(const std::vector<std::vector<int>>& graph)`
  - Contract: sorted output.
  - Tests: self-loop → unsafe; terminal nodes → safe; a node leading into a cycle → unsafe.
  - Large: 10⁴ nodes.
  - CLRS: §22.3 (3e) / §20.3 (4e): white/gray/black coloring and back edges (≈10 min).
- **`reconstruct_itinerary`** · Hard
  - Sig: `std::vector<std::string> findItinerary(std::vector<std::vector<std::string>> tickets)`
  - Contract: start at "JFK"; use every ticket exactly once; lexicographically smallest valid itinerary.
  - Tests: a dead-end trap (`JFK→KUL`, `JFK→NRT`, `NRT→JFK` → JFK, NRT, JFK, KUL); duplicate tickets; a single ticket.
  - CLRS: the end-of-chapter problem "Euler tour" in Ch. 22 (3e) / Ch. 20 (4e) (≈10 min).
- **`alien_dictionary`** · Hard
  - Sig: `std::string alienOrder(const std::vector<std::string>& words)`
  - Contract: any valid order of all the letters that appear; "" if the input is inconsistent. PROBLEM.md notes this is a premium problem written in original words.
  - Tests:
    - validate against the constraints;
    - prefix violation (`{"abc", "ab"}` → "");
    - a cycle → "";
    - a single word (any order of its letters);
    - letters with no constraints are still included.

**CLRS quick reference rows:**
- Strongly connected components (review only): §22.5 / §20.5, ≈15 min.
- Bridges and articulation points: the Ch. 22 / Ch. 20 end-of-chapter problem, ≈20 min.
- Euler tour: the Ch. 22 / Ch. 20 end-of-chapter problem, ≈10 min.
- Max flow (conceptual): §26.2 / §24.2, "The Ford-Fulkerson method"; Edmonds-Karp is analyzed in this section, ≈20 min.
- Bipartite matching (conceptual): §26.3 (3e) / Ch. 25 (4e), ≈15 min.
- A*: not in CLRS.
